# Domain documentation

Before a change affecting identity, registrations, deployments, resource links or roles:

1. read the root glossary [`CONTEXT.md`](../../CONTEXT.md);
2. read the relevant ADRs in [`docs/adr/`](../adr/);
3. use the glossary terms in code, tests and issues.

`CONTEXT.md` is only a glossary. It contains no implementation choices, procedures or detailed specifications.

An ADR only documents a decision that is costly to reverse, surprising without context, and the result of a genuine trade-off. If a change contradicts an existing ADR, explicitly flag the conflict before changing the behavior.

Create new domain documents only when a term or decision is truly established.
